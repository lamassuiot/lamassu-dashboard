# Module Federation spike — findings (2026-11-09)

Stack tested: Vite 8.3.5, React 19, react-router 7, `@module-federation/vite` 1.23.11,
`@module-federation/runtime` 2.9.3, Node 22. A throwaway remote exposing `./module`
was loaded by the shell in **dev** (`vite`) and in **production** (`vite build`, static
server), in headless Chromium. In every run the remote rendered, its own CSS was
applied, and `useLocation()` inside the remote returned the shell's path
(`/spike/a/b`), which proves react-router is a real singleton shared with the shell.

## (a) Runtime import

`registerRemotes` and `loadRemote` come from **`@module-federation/runtime`**
(explicit dependency of the shell). No manual `init()` is needed: the host plugin
initialises the runtime, and `registerRemotes([{ name, entry, type: 'module' }])`
followed by `loadRemote('<name>/module')` works in dev and build.

## (b) Plugin options

Host (`vite.config.mjs`):

```js
federation({
  name: 'lamassu_shell',
  remotes: {},
  dts: false,
  shared: { react, 'react-dom', 'react-router' — singleton + requiredVersion },
})
```

No `build.target` change was needed for the host build.

Remote (`vite.config.ts`):

- `name`, `filename: 'remoteEntry.js'`, `exposes: { './module': './src/module.tsx' }`
- **`dts: false` is required.** Without it the dev server crashes with an unhandled
  rejection in `@module-federation/dts-plugin` (`retrieveRemoteConfig`).
- `build: { target: 'esnext' }`
- Dev server: `server: { port, cors: true, origin: 'http://localhost:<port>' }`
  (the `origin` was always set; it was not tested without it).
- Declare only `react`, `react-dom` and `react-router` in `shared`. `react/jsx-runtime`
  is shared automatically by the plugin. The remote bundle still contains its own
  fallback copy of those libraries, but the shell's copy is the one used at runtime.

## (c) `base`

`base: './'` works: the same build loaded correctly from `/ui/modules/spike/` and
from an unrelated path (`/elsewhere/x/`), because assets resolve relative to where
`remoteEntry.js` was loaded from. An absolute `base` also worked, but only at its own
path. **Use `base: './'` in the template.**

## Other observations

- A `loadRemote` that rejects (dead `entry`) inside a bare `React.lazy` leaves a blank
  page with no message. `RemoteModuleHost` must catch the error and render the error
  panel with Retry.
- `pnpm add` also rewrote the `dotenv` lockfile entry (16.6.1 → 18.0.9): `package.json`
  already required 18 at HEAD and the lockfile was behind.
